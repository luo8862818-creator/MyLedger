# 多笔记账的解析与保存边界

## 规则层

文字和语音最终结果进入同一个 `LedgerBatchParser`，UI 不自行拆账。

1. 规范化全角字符，先识别明确的分句标点。
2. `LedgerAmountParser` 返回金额及字符范围，供单笔和多笔解析复用；过滤日期、时间与数量。
3. 对连续“用途+金额”短句按金额范围分笔，使用统一分类词典识别别名、分类名和收支方向。
4. 继承相对日期上下文，显式的新日期可以覆盖；“合计”仅用于校验，不产生新账单。
5. 任一片段缺信息、金额分配不清、合计不符或存在否定/计划/备选含义时，整批等待用户修改。

每次最多2000字符、20笔。该实现是有明确适用边界的确定性规则解析，不声称理解任意自然语言。

| 描述 | 结果 |
| --- | --- |
| 吃饭20，打车30 | 餐饮支出20元、出行支出30元 |
| 昨天吃饭20，打车30 | 两笔均归属昨天 |
| 吃饭20，吃饭20 | 保留两次消费，不按内容去重 |
| 吃饭20，打车30，合计50 | 两笔，合计只作校验 |
| 吃饭和打车一共50 | 不能分配各笔金额，等待补充 |
| 吃饭20，打车 | 第二笔缺金额，整批不保存 |

## 提交与事务

手动单笔、多笔文字和语音统一提交 `List<Transaction>`：

```text
TransactionEntrySheet
  -> LedgerViewModel.saveTransactions
  -> TransactionRepository.saveAll
  -> TransactionDao.saveAll (@RoomTransaction)
```

任意一笔写入失败会回滚整批。只有全部写入成功，才关闭输入面板并触发一次备份。编辑已有账单仅允许提交一笔，避免多笔复用同一个原记录ID。

语音只在最终结果事件后提交；中间识别结果只展示。取消、切换输入方式或退出后的迟到结果由会话标识丢弃，重复最终回调不会再次提交。

## 展示与滚动

`SmartEntryPreview` 只展示解析结果。`LedgerNavigationItem` 统一导航选中样式与可访问性语义。记账面板固定标题和提交按钮，中间内容独立滚动；禁用面板拖拽接力和边缘拉伸，避免内容到边界后拖走整张面板。

## 回归关注点

- 中文/阿拉伯金额、全角字符、同类重复购买、日期继承与合计一致性。
- 不完整输入、否定、预算、备选项不能直接保存。
- 重复语音事件仅提交一次，批量写入失败不会留下部分记录。
- 编辑保护、键盘弹出后的可操作性及上下滚动边界。
